## Problem
슬라이드 구조(골격)를 내용·디자인과 분리한 도메인 중립 재사용층(`format/`)을 설계했으나, 실제 5단계 파이프라인에서 끝까지 작동하는지 미검증이었다. 첫 형식 `lecture-deck`만 존재하는 상태.

## Solution
실설교("하나님은 누구신가", 교리설교 2강, 엡 1:11)로 라이브 실주행:
- **2단계(아키텍트):** 3질문 → Part 1·2·3으로 슬롯 매핑, 전 슬라이드에 `data-fmt-slot`(표지/목표/아젠다/단원구분/번호본문/마무리) 태깅. 내용유형(대지/예화/봉독)과 슬롯을 **직교** 태깅.
- **4단계(디자이너):** 골격 렌더 — `data-fmt` chrome(kicker/unit-no/unit-title/idmark/pagenum) 부착, 1920×1080 네이티브, 헤더 좌표 앵커.
- **5단계(리뷰어):** Playwright `getBoundingClientRect`로 좌표 구역(키커=좌상, idmark=우상, pagenum=우하, 헤더 y≈80~178) 실측. 21/21 통과.
- 두 사용자 컨펌 게이트 통과(컨펌#1 콘텐츠·컨펌#2 디자인).

## Key Insight
형식층은 **"내용→슬롯 어댑터"만 교체하면 도메인 무관하게 재사용**된다(렌더·검증은 내용 무관). 생성자(4)와 검증자(5)를 잇는 재사용 인터페이스는 **DOM 계약**(`data-fmt-slot`/`data-fmt` + 바운딩박스 구역)이다. 적용 우선순위는 **콘텐츠 진실성[절대] > 형식 > 디자인** — 형식은 빈 골격이라 도메인 규칙을 못 넘는다(이번에도 주기도문 제외·역본 원고보존이 형식보다 우선했다).

## Context
PPT 제작 에이전트 — format층 첫 소비자(설교 파이프라인) 라이브 실주행. 오케스트레이터가 형식 결정(사용자 지정 lecture-deck) → 아키텍트 전달 → 단계별 조율. user-brain ST-001~004(아젠다 3분할·수미상관)와도 정합. 형식 선택 규칙: 사용자 지정 > 덱 성격 추천 > 자유 구조(미적용).
