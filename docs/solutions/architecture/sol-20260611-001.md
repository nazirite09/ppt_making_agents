## Problem
다단계 서브에이전트 파이프라인(메인 세션이 오케스트레이터)을 워크플로우 점검했더니, 진짜 리스크는 설계 결함이 아니라 **정합성 부채**였다. 두 종류로 나타났다:
1. **문서↔실체 어긋남** — CLAUDE.md가 존재하지 않는 `scripts/generate_image.py` 실행법·신학 가드를 문서화, 최종 산출물 컨벤션이 둘로 갈라짐(slide-NN.html vs 단일 index.html), 형식 슬롯·좌표가 "에이전트 무수정" 약속과 달리 3개 에이전트 프롬프트에 하드코딩.
2. **암묵 관행 소멸 위험** — 2단계 품질을 사실상 견인하던 「오케스트레이터 브리프」(형식 매핑·역본 정책·불변식 리마인더), 게이트 통과 기록, git 커밋 주체가 **어떤 규약 문서에도 없었다**. 오케스트레이터는 세션마다 새로 태어나므로 규약에 없는 관행은 다음 세션에서 사라진다.

## Solution
점검을 HTML 보고서 + MD 개선안(심각도 🔴/🟡/🟢, 적용 파일 매핑 포함)으로 산출한 뒤 로드맵을 순차 실행:
- 허상 스크립트는 **실제 구현 + 에이전트 정의에 호출 절차 연결**(또는 제거)로 닫는다 — "CLAUDE.md의 모든 명령이 실행 가능"을 완료 기준으로.
- 갈라진 컨벤션은 **둘 다 공식화**(기본형/예외형)하고 감수 절차를 양쪽에 성문화.
- 하드코딩된 형식값은 **사양서(format/<type>.md §DOM 계약)를 단일 진실 소스로 위임**, 에이전트는 참조만.
- 암묵 관행은 **템플릿으로 성문화**(브리프 7항목)하고, 휘발성 상태는 **파일로 고정**(`00-status.md` — 단계·rev·게이트 결정).
- 재작업 루프에 **상한+에스컬레이션**, 판정 어휘를 3종으로 **고정**.

## Key Insight
오케스트레이터가 매 세션 콜드 스타트하는 시스템에서 **"잘 되고 있는 암묵 관행"은 자산이 아니라 부채**다 — 규약(CLAUDE.md/에이전트 정의/파일)에 박히지 않으면 다음 세션에 소멸한다. 점검 시 설계 우아함보다 **문서가 약속한 것이 실제로 존재·실행 가능한지**, **세션 간에 살아남는 상태가 파일로 고정됐는지**를 먼저 감사하라. 좋은 관행을 발견하면 칭찬하지 말고 즉시 성문화하는 것이 가장 빠른 거버넌스 개선이다.
