## Problem
초기 설계에서 공식 Anthropic `pptx` 스킬이 "html2pptx" 변환기를 제공한다고 가정하고 `pptx-builder` 에이전트를 그 워크플로에 맞춰 설계했다. 실제 스킬 구조를 확인하지 않은 가정이었다.

## Solution
스킬을 설치(`~/.claude/skills/pptx/`)해 실제 워크플로를 확인했다:
- **생성(scratch):** `pptxgenjs`(Node)로 슬라이드를 프로그래밍 방식 생성
- **템플릿 편집:** OOXML unpack → 수정 → pack
- **읽기·QA:** `markitdown`(텍스트 추출), `soffice`(LibreOffice)→`pdftoppm`(Poppler)로 이미지화 후 검수
- 자동 html→pptx 변환기는 **없음** → 네이티브 슬라이드는 pptxgenjs로 *재현(recreate)* 한다.

`pptx-builder`를 pptxgenjs 재현 + (복잡 슬라이드) Playwright PNG 하이브리드로 재작성했다.

환경(이 머신, 2026-06-04 기준):
- 설치됨: node v24.15 + `pptxgenjs@4.0.1`, `markitdown 0.1.6`, `python-pptx 1.0.2`, Pillow.
- **미설치: LibreOffice(soffice), Poppler(pdftoppm)** → pptx 자체의 이미지 렌더 QA가 제한적.

Windows 게이트:
- 전역 설치된 pptxgenjs를 node가 찾도록 실행 전 `NODE_PATH=$(npm root -g)` 설정.
- markitdown/python으로 한글 pptx 텍스트를 콘솔 출력할 때 `PYTHONUTF8=1`(또는 `chcp 65001`); 확실히 하려면 UTF-8 파일로 추출해 확인.

## Key Insight
스킬/도구의 *실제* 워크플로와 의존성을 설치·검증한 뒤 그 위에 설계하라. 이름만 보고 기능(html2pptx 같은)을 가정하지 말 것. 검증은 스모크 테스트(한글 포함 생성→읽기)로.
