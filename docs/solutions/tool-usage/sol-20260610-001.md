## Problem
로컬 HTML 슬라이드를 Playwright MCP로 렌더/스크린샷/검증하려는데 `browser_navigate`가 `file://` 경로에서 실패한다 — `Access to "file:" protocol is blocked`. design-reviewer(5단계) 문서가 `file://`로 열게 돼 있어 그대로면 렌더 감수 자체가 불가했다.

## Solution
대상 디렉터리를 로컬 HTTP로 서빙하고 `localhost`로 접근한다:
- `py -m http.server <PORT> --directory "<dir>"` (백그라운드) → `browser_navigate http://localhost:<PORT>/slide-NN.html`.
- 뷰포트는 슬라이드 **실제 body 크기**로 `browser_resize`(1280×720 또는 형식 네이티브 1920×1080) — 하드코딩 금지(좌표 검증이 어긋남).
- 구조/위치 검증은 `browser_evaluate`로 `getBoundingClientRect`를 질의해 객관 판정(스크린샷 눈대중보다 정확).
- (연관) Figma MCP `get_screenshot`이 주는 이미지 URL은 **단명** → `curl`로 파일 저장 후 Read.

## Key Insight
Playwright MCP는 `file://`를 막는다. 로컬 HTML은 **항상 localhost http로 서빙**한 뒤 navigate/screenshot/evaluate 한다. 위치 기반 검증은 `browser_evaluate` + bounding box로 객관화한다.

## Context
PPT 제작 에이전트 — 형식(format)층 배선 중 design-reviewer #9(형식 충실도)를 `data-fmt` DOM 계약 + `browser_evaluate`로 검증하며 발견·수정. `file://`는 사전 문서 결함이었고, 같은 김에 뷰포트 하드코딩(1280)도 실제 베이스로 고쳤다.

**재확인(2026-06-10, 「하나님은 누구신가」 실주행):** 오케스트레이터 직접 검증에서도 `file://` 차단 재현 → `py -m http.server 8765`로 우회. 다만 이번엔 bounding box만으론 fade-in 빈 프레임을 못 잡아 `opacity` 측정이 필요했다([[sol-20260610-004]]).
