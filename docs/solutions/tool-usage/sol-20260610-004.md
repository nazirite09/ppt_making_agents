## Problem
design-reviewer가 21장 슬라이드를 Playwright로 감수하며 `getBoundingClientRect` 좌표 질의로 ✅통과시켰다. 그러나 navigate 직후 스크린샷이 `.animate`(fade-in: opacity 0→1) 요소의 **빈 초기 프레임**을 캡처했다 — 한 슬라이드(18)가 두 번 연속 본문이 텅 빈 채로 찍힘. bounding box는 opacity와 무관하게 정상 박스를 보고하므로 위치 검증만으론 이 결함이 안 잡혀 거짓 안심을 줬다.

## Solution
`browser_evaluate`로 `opacity`/`visibility`를 좌표와 함께 측정 → 모든 콘텐츠가 `opacity:1`·`visible`·정상 위치(headline top 405 등)임을 확인, 빈 화면은 캡처 타이밍(애니메이션 전)임을 규명. 애니메이션 완료 후 재캡처하니 정상 렌더. 대응 옵션:
- (a) 스크린샷 전 애니메이션 완료 대기(시간 경과 / `browser_wait_for`),
- (b) `opacity`/`visibility`를 좌표와 함께 측정해 가시성 확인,
- (c) 정적 추출(PDF·이미지)이 목적이면 진입 애니메이션 비활성화(`prefers-reduced-motion` / 플래그).

## Key Insight
`getBoundingClientRect`는 **레이아웃 박스만** 본다 — `opacity:0`·`visibility:hidden` 요소도 "정상 위치"로 보고한다. "보이는가"를 검증하려면 opacity/visibility를 측정하거나 애니메이션 완료를 보장하라. **정적 산출물에 진입 애니메이션이 있으면 navigate 직후 스크린샷은 빈 프레임을 잡는다** — 생성자·리뷰어가 자동 통과시켜도 오케스트레이터의 직접 렌더로 잡아야 한다([[sol-20260610-001]]의 "bounding box로 객관 검증" 권고를 보완: 박스는 가시성을 못 본다).

## Context
PPT 제작 에이전트 — "하나님은 누구신가" 5단계 후 오케스트레이터 최종 검증에서 발견. 덱은 fade-in을 투사 발표 효과로 의도(사용자가 유지 결정). 그래서 "끄기"가 아니라 "정적 캡처 시 완료 대기"가 이 프로젝트의 대응.
