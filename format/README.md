# `format/` — 슬라이드 형식(골격) 레지스트리

슬라이드의 **구조(골격)**를 규정하는 **도메인 중립 재사용층**. 디자인 시스템이 *룩*을 고르듯, 형식은 *구조*를 고른다 — 설교·행사·강의 등 **어떤 토픽에도** 쓰인다.

## 3층 모델
| 층 | 정하는 것 | 위치 |
|---|---|---|
| 내용 | 무엇을 말하나 | 소비자(설교=스토리라인 등) |
| **형식 ← 여기** | 슬라이드 유형·위치·반복·순서(골격) | `format/<type>.md` |
| 디자인 | 어떻게 보이나(색·폰트·이미지) | `design/*.md` · visualize |

- **형식 ≠ 디자인.** 형식=무엇이 어디에·무엇이 반복되나(위치·슬롯·순서). 디자인=색·폰트·장식·톤.
- **규약:** 덱 유형마다 **파일 1개**(`format/<type>.md`). 각 파일은 슬롯·순서·헤더 해부·전역 chrome·**필수/선택 슬롯**·**네이티브 베이스**·**DOM 계약**을 담는다.

## 사용 가능한 형식
| 형식 | 적합 덱 | 트리거 | 파일 |
|---|---|---|---|
| `lecture-deck` | 다단원 교육·강의·연속 세션 | 단원/강·로드맵·반복 헤더·번호 본문 | [`lecture-deck.md`](lecture-deck.md) |

*(레퍼런스로 계속 추가 — 아래 「형식 추가」 참고. 예정: event-intro, schedule-summary …)*

## 형식 선택 규칙 (우선순위)
1. **사용자 지정**(메타 `형식 요청`)이 최우선.
2. 없으면 **덱 성격으로 추천**(위 표의 트리거 매칭).
3. 그래도 모호하면 **`지정 없음(자유 구조)`** — 형식 골격 미적용, 생성자 재량(현행 동작).

## 가드
- 형식은 **빈 구조 골격일 뿐**, 소비자의 **콘텐츠 진실성**(설교=원고 충실성)·**도메인 범위 규칙**(설교=예배 순서 제외)을 **넘지 못한다.** 충돌 시 콘텐츠 우선.
- 적용 우선순위: **콘텐츠 진실성[절대] > 형식 > 디자인.**

## 형식 추가 (성장)
1. 레퍼런스(Figma·기존 덱 등)에서 골격을 추출해 `format/<new>.md` 작성 — 슬롯·순서·헤더 해부·chrome·**필수/선택 슬롯·네이티브 베이스·DOM 계약** 포함(`lecture-deck.md` 형식 따름).
2. 위 「사용 가능한 형식」 표에 한 행 추가.
3. **에이전트 수정 불필요** — 파이프라인은 레지스트리와 `<type>` 변수로 동작.
4. 2번째 형식이 생기면 공통 chrome·DOM 계약을 `format/_base.md`로 추출한다.

## 소비자 (이 형식을 쓰는 곳)
- **설교 PPT 파이프라인**(첫 소비자): 2단계 아키텍트가 콘텐츠를 슬롯에 매핑·구조화 → 4단계가 렌더 → 3·5단계가 감수.
- **렌더(4)·형식검증(5)은 내용 무관**이라, 다른 토픽(행사·강의)도 자기 *콘텐츠→슬롯* 어댑터만 두면 그대로 재사용.
