# 사용자 세컨드 브레인 — user-brain.md

> 예배 설교 PPT 파이프라인의 **모든 에이전트가 공유**하는 사용자 선호 지식베이스.
> 각 에이전트는 작업 시작 시 이 파일을 읽고, **사용자 승인 후에만** 갱신한다(제안형).
> 사용자가 직접 편집해도 된다. git으로 변경 이력이 보존된다.
> 적용 우선순위: (1) 원고 충실성[절대] > (2) 필수 > (3) 중요 > (4) 선호 > (5) 실험.
>
> **scope:** `storyline`(sermon-storyline-architect) · `design`(slide-visual-designer) · `global`(전 에이전트).
> 각 에이전트는 **자기 scope + global**만 적용·수정한다.
> ※ 이 브레인의 **파일 쓰기 주체는 `sermon-storyline-architect` 1명**(storyline·global 직접, design은 디자이너 제안분 대리 커밋 — ID `DS-###`). `slide-visual-designer`는 읽기·적용(design·global) + 컨펌#2 피드백에서 design 규칙 후보 제안. 디자인 취향(폰트 시스템·색·테마·저작권 등)은 `design` scope에 쌓인다. git 커밋은 오케스트레이터가 한다.

## 선호 프로파일 (자화상)

> 에이전트가 규칙·피드백에서 도출·유지하는 사용자 취향 요약(3~8문장).
> 작업 시작 시 **가장 먼저** 읽어 판단을 priming하고, 규칙이 못 다루는 새 상황은 이 프로파일로 일반화 판단한다. 규칙이 바뀌면 갱신한다.

이 사용자는 정보를 **직렬 나열이 아니라 관계·구조**로 보여주는 것을 선호한다. 여러 항목을 요약할 때 타임라인이나 번호 카드처럼 줄세우기보다, 항목 간 연결과 위계가 드러나는 **다이어그램**을 기대한다(ST-001). 본론에 들어가기 전 **개념·용어를 한 장으로 먼저 정의**하고 넘어가는 것을 중시하며(예: 오버뷰 앞 '교리란?' — ST-002), 청중이 토대를 잡은 뒤 내용을 받기를 원한다. **도입은 압축**을 선호해 앞부분이 비대해지는 것을 경계하고 도입 슬라이드를 최소화한다(ST-003). 분량 면에서 **중복을 강하게 싫어해**, 같은 내용은 한 슬라이드에 일원화하고 다른 곳의 반복을 적극 제거하기를 바란다(GL-001, 전 에이전트 공통). 구성의 마무리로 **오프닝↔결론 수미상관**을 좋아해, 도입에서 보여 준 구조를 결론에서 같은 형태로 다시 읽어 주는 것을 선호한다(ST-004).

종합하면 **압축된 도입 → 선개념 정의 → 관계형 구조로 본론 전개 → 중복 제거 → 도입과 호응하는 결론**이라는, 군더더기 없이 구조가 또렷한 흐름을 지향한다. 미해결 긴장: "도입 압축(ST-003)"과 "본론 전 개념 정의 한 장 삽입(ST-002)"이 짧은 설교에서 슬라이드 예산을 두고 부딪힐 수 있다 — 어느 쪽을 우선할지는 데이터가 더 쌓이면 가려질 것이다. (모든 항목 provisional, 관찰 1회 — 추가 컨펌으로 검증 필요.)

## 가중치 모델

- **범주(점수 = 중요도):** 필수 80–100 · 중요 55–79 · 선호 30–54 · 실험 1–29
- **상태(성숙도/확신):** provisional(검증 중) · established(반복·검토로 확립) · retired
- **신규 초기점수(신호강도):** 강함(반드시/꼭/항상/거절성 변경) = 60 · 보통 = 35 · 약함 = 20
  - 승인 시 사용자가 범주를 지정하면 그 값을 우선한다.
- **조정:** 재확인 +15(최근확인 갱신) · 위반/반대 −20(+모순 플래그)
- **감쇠:** 실험·선호만 5설교 미확인 시 stale → retired 후보. **원칙·필수는 감쇠하지 않는다.**
- 점수가 인접 범주 임계를 넘으면 범주를 자동 승격/강등한다(변경 로그 기록).
- **유형:** 선호(do) · 금지(don't = 하드 회피, 절대 위반 금지) · 표기(사실·표준, 예: 역본 통일).
