실증된 강점 (실산출물 근거)

비평가 게이트가 실제로 결함을 잡는다. 올리브 덱에서 🔴 푸터 겹침을 컨펌 전에 적발(03-slides.review.md), 「하나님은 누구신가」에서 역본 메타·본문 모순을 🔴로 적발해 rev 2에서 해소. 감수가 형식적 절차가 아니라 작동하는 품질 게이트임이 입증됨. 특히 역본 사례는 킥오프 브리프가 역본을 지정했는데도 아키텍트가 메타를 잘못 선언한 것을 리뷰어가 잡은 것 — 다층 방어가 설계 의도대로 동작했다.
불변식이 전 에이전트에 일관 전파. 원고 충실성 절대 우선 · 예배 순서 제외 · 브레인/형식이 충실성을 못 넘는 가드가 4개 에이전트 정의 모두에 같은 우선순위로 명시. 「하나님은 누구신가」에서 주기도문 슬라이드 제외가 실제 적용됨.
감수가 증거 기반. design-reviewer는 Playwright 실측(스크린샷·바운딩박스·콘솔), storyline-reviewer는 원고 문장 단위 대조 + 슬라이드 번호·원고 근거 인용 강제("추측 금지"). 실리포트가 원고 line 번호까지 인용함을 확인.
형식층의 DOM 계약(data-fmt)이 주관 감수를 객관 검증으로 전환. 라이브 덱 21장 전부 슬롯 태그 부착 확인. 렌더(4)·검증(5)이 내용 무관이라 재사용 가능하다는 주장도 구조상 타당.
지식 이원화가 명확. 취향(user-brain: scope·중요도/성숙도 분리·컨펌-온리) vs 해결책(docs/solutions: 카테고리·confidence·재강화)이 섞이지 않게 분리. 두 KB 모두 실제 적재·운용 중.

2.3 오케스트레이터(메인 세션) 책무 감사

이 파이프라인은 별도 오케스트레이터 파일 없이 메인 세션이 오케스트레이터다. 책무가 CLAUDE.md에 산재해 있어, 어디까지가 규약이고 어디부터가 관행인지 감사했다:

책무규약화 상태비고
① 작업 폴더 생성 (sermons/<날짜-제목>/)⚠️ 규약 위반규약은 날짜-제목인데 실폴더 2건 모두 날짜 없음(교리설교-6강-복습 · 하나님은-누구신가) (→ Y8).
② 인제스트 + 오케스트레이터 브리프 작성❌ 미성문화두 사례 모두 01-script.md 머리에 우수한 브리프(임무 정의·형식 매핑·톤·역본·불변식 리마인더·브레인 부합 메모)가 실재하나, 어떤 문서에도 이 관행이 규약으로 없다. 세션이 바뀌면 품질이 복불복 (→ Y10).
③ 형식 결정 (지정>추천>없음) + 디자인 요청 수집✅ 규약화CLAUDE.md + format/README 선택 규칙 명확. 실브리프에서 매핑 지시까지 수행됨.
④ 단계 순차 호출 + 게이트 정지✅ 규약화"사용자 컨펌 없이 다음 단계 진행 금지" 명시.
⑤ 재작업 라우팅 (❌/⚠️ → 생성자)✅ 규약화단, 반복 상한 부재 (Y9).
⑥ 브레인 커밋 모드 재호출✅ 규약화아키텍트 정의·CLAUDE.md 양쪽에 흐름 명시.
⑦ git 커밋 (산출물·브레인)❌ 암묵아키텍트는 Bash가 없어 git 커밋 불가 — 실제 커밋은 오케스트레이터가 수행(git 이력 확인). 그러나 CLAUDE.md의 "architect가 쓰기·커밋"은 파일 갱신 의미라 용어가 중의적이고, 커밋 시점 규약도 없음 (→ G7, Y7).
⑧ 파이프라인 상태 기록❌ 부재게이트 통과·rev·킥오프 결정이 세션 대화에만 존재 (→ Y3).

요약: 호출·게이트·브레인 루프(③~⑥)는 규약이 탄탄한 반면, 경계 바깥 책무(폴더·브리프·커밋·상태 기록 = ①②⑦⑧)가 전부 암묵이다. 오케스트레이터는 세션마다 새로 태어나므로, 암묵 책무는 곧 세션 간 비일관성이 된다 — 이번 점검에서 발견된 규약 위반(Y8)·stale 판정(Y3)이 그 증상.

6. 발견 사항 상세

🔴 R1 — 필수

AI 이미지 생성 플로우가 실체 없음 — 신학 가드도 미강제

증거: scripts/ 폴더가 저장소에 없고 git log --all -- scripts/도 빈 결과. 그런데 CLAUDE.md는 ① 명령 섹션에 py scripts/generate_image.py … 실행법, ② "POLICY 블록이 강제한다"는 신학 이미지 가드를 명시. 4단계 디자이너 정의에는 이미지 생성 언급이 아예 없어 실행 주체도 정의돼 있지 않다.

영향: 이미지가 필요한 설교에서 명령이 즉시 실패하고, "하나님·예수 얼굴 묘사 금지" 가드는 문서 속 선언으로만 존재한다 (현재는 브리프의 리마인더 한 줄이 유일한 방어선).

권고: 양자택일 — (a) 스크립트를 실제 구현(POLICY 블록 포함)하고 디자이너 정의 작업 절차에 "이미지 필요 시 호출 → 실패 시 SVG 폴백" 1줄 추가, 또는 (b) 당분간 SVG/일러스트-온리 정책으로 확정하고 CLAUDE.md 명령·가드 단락을 제거(가드 원칙은 디자이너 정의 가드레일로 이동).
🔴 R2 — 필수

최종 산출물 컨벤션 분기 — 규약(slide-NN.html) vs 실제 확정본(단일 index.html)

증거: CLAUDE.md 작업 폴더 규약과 디자이너 정의는 "슬라이드당 1개 독립 HTML"을 핵심 설계 결정으로 명시. 그러나 확정된 교리설교-6강-복습 최종본 03-slides/는 단일 index.html(22개 section, 62KB)뿐이다. design-reviewer는 이를 정의에 없는 ad hoc 방식(section:nth-of-type(N) 요소 스크린샷)으로 감수했고, 해당 리포트가 가리키는 경로(03-slides-olive-roadmap/)는 정리 커밋으로 사라져 추적성이 끊겼다. 반면 「하나님은 누구신가」는 규약대로 slide-NN.html 21장 + 공유 deck.css.

영향: 같은 "최종 산출물"이 두 가지 상이한 형태로 존재 — 후속 세션·에이전트가 어느 쪽이 규약인지 판단할 수 없고, 감수 절차도 형태별로 달라진다.

권고: 정책 결정 후 문서화 — (권장) 두 형태 모두 공식화: 기본=slide-NN.html(파이프라인 표준), 예외=단일 파일 덱(연속 스크롤 발표용, 사용자 명시 요청 시)으로 CLAUDE.md에 명시하고, 디자이너·design-reviewer 정의에 단일 파일 제작·감수 절차를 정식 추가. 또는 올리브 덱을 규약대로 재분할. 어느 쪽이든 리포트의 stale 경로는 한 줄 수정.

🟡 Y9 — 권장 (2차 보강 신규)

생성자↔비평가 재작업 루프의 종료 조건 부재

증거: "🔴가 하나라도 있으면 통과 불가 → 생성자 재작업"은 명확하나, 반복 상한과 에스컬레이션 규칙이 없다. 비평가가 매 라운드 새 🔴를 내면(또는 생성자와 견해가 갈리면) 게이트에 도달하지 못한 채 opus/max 호출이 무한 누적될 수 있다. 현재까지는 1~2회 수렴(실사례)했지만 이는 운이지 설계가 아니다.

권고: CLAUDE.md 파이프라인 규약에 1줄: "같은 게이트에서 재작업 2회 후에도 ❌면 오케스트레이터가 쟁점 요약과 함께 사용자에게 에스컬레이션(잔여 🔴 목록 + 생성자/비평가 견해 차이)." 인간 게이트가 이미 있으므로 조기 에스컬레이션이 자연스러운 해소책.
🟡 Y10 — 권장 (2차 보강 신규)

최우수 관행 "오케스트레이터 브리프"가 미성문화 — 세션 간 품질 복불복

증거: 두 설교 모두 01-script.md 머리에 탁월한 브리프가 실재한다: 작업 성격 정의 · 형식 매핑 지시(슬롯←콘텐츠) · 대상·톤 · 역본 정책 · 불변식 리마인더 4종 · 세컨드 브레인 부합 메모까지. 이 브리프가 2단계 아키텍트의 품질을 사실상 견인하고 있다(스토리라인이 브리프 구조를 그대로 따름). 그러나 이 관행은 어떤 규약 문서에도 없다 — CLAUDE.md 1단계는 "원고 → 01-script.md"라고만 말한다. 오케스트레이터는 세션마다 새로 시작하므로, 규약에 없는 관행은 다음 세션에서 사라질 수 있다.

권고: CLAUDE.md 1단계 항목에 브리프 템플릿을 성문화: 01-script.md 상단에 ① 작업 성격(단일 설교/복습/행사) ② 형식 결정 + 슬롯 매핑 힌트 ③ 대상·톤 ④ 역본 정책 ⑤ 불변식 리마인더 ⑥ 브레인 부합 메모 ⑦ 원본 출처·추출 방법. 기존 2건의 브리프가 그대로 모범 예시가 된다.
🟢 G1~G8 — 선택

G6 감수 루브릭이 이미 점수화 가능한 형태 — 설교 5건·형식 2종 쌓인 뒤 autoresearch로 아키텍트 출력 eval 하니스 구축 검토. G7 (신규) "커밋" 용어 중의성 해소 — 브레인 파일 갱신(아키텍트 커밋 모드) vs git 커밋(오케스트레이터, 아키텍트는 Bash 없음)을 CLAUDE.md에서 구분 표기. G8 (신규) 비평가 2종의 Write 권한이 규범으로만 제어 — 두 리뷰어 정의에 "리포트 파일 외 쓰기 금지" 1줄로 명시화.
